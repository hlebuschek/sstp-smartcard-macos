# SSTP VPN для macOS со смарт-картой

Клиент SSTP для macOS, который умеет аутентифицироваться по EAP-TLS
сертификатом, лежащим на смарт-карте (SafeNet eToken / IDPrime, JaCarta PKI
и совместимые).
Закрытый ключ не покидает токен: каждая подпись во время рукопожатия выполняется
самой картой через PKCS#11.

Написан потому, что ни один доступный на macOS SSTP-клиент со смарт-картами не
работает, а корпоративный RRAS-сервер другой аутентификации не принимает.

## Что уже работает

- Туннель до Windows RRAS: SSTP поверх TLS, PPP (LCP + IPCP), EAP-TLS,
  криптографическая привязка SSTP.
- Полный туннель и раздельный (split): произвольный список сетей.
- DNS: в полном туннеле все запросы уходят на корпоративные серверы (как делает
  штатный клиент Windows), в раздельном — только корпоративные домены, остальной
  интернет резолвится как раньше.
- Восстановление маршрутов и DNS, даже если клиент был убит, а не остановлен.
- Профили подключений с привязкой к конкретному сертификату.

## Как устроено

Три слоя:

| Слой | Где | Зачем |
| --- | --- | --- |
| Ядро | `sstp/` | Протокол, работа с картой, маршруты и DNS |
| Демон | `sstp daemon` | Запускается от root через launchd, слушает unix-сокет |
| Интерфейс | `gui/` | Приложение SwiftUI, общается с демоном по JSON |

Root нужен ради `utun`, таблицы маршрутов и `networksetup`. Интерфейс работает
в пользовательской сессии и ничего привилегированного не делает сам.

### Модули ядра

- `token.py` — PKCS#11: перечисление карт, чтение сертификатов **без логина**,
  подпись после `C_Login`.
- `transport.py`, `protocol.py` — внешний TLS до сервера и управляющие пакеты
  SSTP.
- `tls/` — **собственная реализация TLS 1.2**. Системный TLS не подходит: в
  EAP-TLS записи рукопожатия едут внутри EAP-пакетов, подписывать нужно на
  карте, а из полученного соединения нужно экспортировать master secret для
  криптографической привязки SSTP. Ни одно из трёх системный стек не даёт.
- `ppp/` — кадрирование PPP, LCP, IPCP и EAP.
- `crypto_binding.py` — Higher-Layer Authentication из MS-SSTP.
- `net.py` — `utun`, маршруты, DNS и сохранение прежнего состояния системы.
- `trust.py` — корпоративный CA берётся из связки ключей macOS: в bundle
  сертификатов Python его нет.

## Установка

Готовый архив лежит в [релизах](../../releases). Собран для Apple Silicon и
подписан ad-hoc, без Apple Developer ID.

1. Распаковать и перетащить `SSTP VPN.app` в «Программы».
2. Снять карантин — иначе Gatekeeper не пустит приложение без подписи Apple.
   Открыть его, получить отказ, затем в «Системных настройках» →
   «Конфиденциальность и безопасность» нажать **«Всё равно открыть»**. То же
   самое одной командой:

   ```sh
   xattr -dr com.apple.quarantine "/Applications/SSTP VPN.app"
   ```

3. Запустить приложение и нажать **«Установить службу»**. Оно спросит пароль
   администратора, скопирует ядро в `/usr/local/libexec/sstp` и зарегистрирует
   демон `local.sstp.daemon` в launchd. Дальше служба поднимается сама при
   загрузке.

Python и зависимости лежат внутри бандла — ставить отдельно ничего не нужно.
Нужен только **драйвер PKCS#11 от производителя токена**: SafeNet Authentication
Client (`/usr/local/lib/pkcs11/`) или Единый Клиент JaCarta
(`/Library/Frameworks/jcPKCS11-2.framework/`). Распространять их нельзя, но у
владельца такой карты он уже стоит. Если установлено несколько драйверов,
клиент сам выбирает тот, который видит вставленную карту.

Удалить всё:

```sh
sudo "/Applications/SSTP VPN.app/Contents/Resources/sstp.sh" uninstall
```

## Настройка

Профиль — именованный набор настроек; их может быть несколько. Профиль
запоминает выбранный сертификат по `CKA_ID`. Если на вставленной карте этого
сертификата нет, приложение предупредит и **не** подключится: молча уйти в
туннель под чужой учётной записью хуже, чем отказать.

- **Сервер** — имя хоста SSTP.
- **Сертификат** — список читается с карты без PIN, рядом показан срок действия.
- **PIN** — спрашивается при каждом подключении и нигде не сохраняется.
- **Весь трафик через VPN** — выключите для раздельного туннеля.
- **Сети** — что заворачивать в туннель в раздельном режиме, например
  `172.16.0.0/12 10.0.0.0/8`. SSTP маршруты не передаёт: Windows тоже берёт их
  из настроек подключения, а не от сервера. Пустой список означает, что в
  туннель не пойдёт ничего.
- **Домены** — список доменов оставит на корпоративных серверах только их
  (через `/etc/resolver/`), а остальной интернет будет резолвиться как раньше.
  Если оставить пустым, в полном туннеле корпоративный DNS становится системным
  (как в Windows), а в раздельном берётся домен из UPN сертификата: заворачивать
  все запросы в туннель, через который уходит только часть сетей, значит
  положить резолвинг всего остального.

## Командная строка

Внутри бандла лежит полноценный CLI:

```sh
SSTP="/Applications/SSTP VPN.app/Contents/Resources/sstp.sh"

"$SSTP" modules                 # найденные библиотеки PKCS#11
"$SSTP" list                    # сертификаты на карте
"$SSTP" status                  # активный туннель
sudo "$SSTP" connect vpn.example.com --cert 3 --no-default-route \
     --route 172.16.0.0/12
sudo "$SSTP" disconnect         # вернуть маршруты и DNS
```

Журнал демона — `/var/log/sstp.log`.

## Сборка

Нужны Xcode с Swift 6 и сеть. Python ставить не надо: скрипт скачивает
относимый рантайм сам.

```sh
gui/make-app.sh
```

Скрипт скачивает [python-build-standalone](https://github.com/astral-sh/python-build-standalone),
ставит в него `requirements.txt`, кладёт рядом пакет `sstp`, собирает
приложение и упаковывает всё в `gui/build/SSTP VPN.app` и `SSTP-VPN.zip`.
Рантайм кэшируется в `gui/build/runtime`, поэтому повторные сборки быстрые.

Для работы с ядром напрямую хватит обычного venv:

```sh
python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt
sudo .venv/bin/python -m sstp list
```

## Ограничения

- Только **Apple Silicon**: колесо `cryptography` в сборке arm64-only.
- Нет подписи Apple Developer ID и нотаризации — отсюда ручное снятие карантина.
- Драйвер PKCS#11 не входит в комплект.
- Проверено на macOS 15 против Windows RRAS с шифрсьютом
  `ECDHE_RSA_AES_256_GCM_SHA384`.

## Безопасность

- PIN не кэшируется, не передаётся в `argv` (виден в `ps`) и затирается после
  логина.
- Данные с карты перечитываются заново при каждом подключении: карта может
  оказаться другой.
- Установщик копирует ядро в `/usr/local/libexec` и делает его `root:wheel`.
  Запускать root-демон прямо из `/Applications` нельзя: бандл принадлежит
  пользователю, и любой процесс от его имени подменил бы код, который root
  выполнит при следующей загрузке.
